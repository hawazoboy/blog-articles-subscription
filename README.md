# معرفی پروژه

Blog Stand یک سامانه مدیریت محتوا (CMS) سبک و مدرن است که امکان ایجاد، مدیریت و انتشار مقالات را فراهم می‌کند.

در این پروژه تلاش شده است تا علاوه بر سادگی رابط کاربری، تمامی قابلیت‌های اصلی یک وبلاگ حرفه‌ای پیاده‌سازی شود.

کاربران می‌توانند:

* ثبت نام کنند.
* وارد حساب کاربری شوند.
* رمز عبور خود را بازیابی کنند.
* مقالات را مشاهده کنند.
* جزئیات هر مقاله را مطالعه کنند.
* از طریق فرم تماس با مدیر سایت ارتباط برقرار کنند.

در سمت مدیر سیستم نیز امکان مدیریت کاربران، مقالات و پیام‌های تماس وجود دارد.

# هدف پروژه

هدف اصلی این پروژه ایجاد یک بستر مناسب برای انتشار محتوای آموزشی و خبری است.

# معماری سیستم

پروژه بر اساس معماری **Monolithic Web Application** توسعه یافته است.

الگوی اصلی مورد استفاده:

> Django MTV (Model - Template - View)

این معماری باعث جداسازی مناسب بخش‌های مختلف پروژه شده و توسعه و نگهداری سیستم را ساده‌تر می‌کند.

---

* نمایش صفحات
* دریافت اطلاعات کاربران
* اعتبارسنجی اولیه فرم‌ها
* نمایش خطاها

---

### Business Logic Layer

وظایف:

* پردازش درخواست‌ها
* مدیریت قوانین سیستم
* مدیریت احراز هویت
* تولید Token
* مدیریت Session
* ارسال ایمیل

---

### Data Access Layer

وظایف:

* ارتباط با پایگاه داده
* مدیریت مدل‌ها
* اجرای Migrationها
* ذخیره و بازیابی اطلاعات

# ۲. مهندسی نیازمندی‌ها (Software Requirements Engineering)

مهندسی نیازمندی‌ها یکی از مهم‌ترین مراحل توسعه نرم‌افزار است که در آن نیازهای کاربران و ذی‌نفعان شناسایی، تحلیل و مستندسازی می‌شود. در پروژه **Blog Stand** تلاش شده است تا تمامی قابلیت‌های اصلی مورد نیاز یک سامانه مدیریت وبلاگ در قالب نیازمندی‌های عملکردی و غیرعملکردی تعریف شوند.

---

# منابع استخراج نیازمندی‌ها

نیازمندی‌های این پروژه بر اساس منابع زیر استخراج شده‌اند:

* مصاحبه با کاربران بالقوه (دانشجویان، اساتید و کاربران وب)
* بررسی نمونه‌های مشابه
* تحلیل نقاط ضعف سیستم‌های موجود
* بررسی نیازهای مدیر وب‌سایت
* رعایت استانداردهای توسعه نرم‌افزار

---

# نیازمندی‌های عملکردی (Functional Requirements)

نیازمندی‌های عملکردی مشخص می‌کنند که سیستم باید چه قابلیت‌هایی را در اختیار کاربران قرار دهد.

---

## FR-01 : ثبت‌نام کاربران

سیستم باید امکان ایجاد حساب کاربری جدید را فراهم کند.

### اطلاعات مورد نیاز

* نام کاربری
* ایمیل
* رمز عبور

### قوانین

* ایمیل نباید تکراری باشد.
* نام کاربری باید یکتا باشد.
* اطلاعات باید اعتبارسنجی شوند.
* پس از ثبت‌نام، رمز عبور به صورت هش شده ذخیره گردد.

---

## FR-02 : ورود کاربران

کاربران باید بتوانند با استفاده از اطلاعات حساب خود وارد سیستم شوند.

### فرآیند

1. وارد کردن ایمیل یا نام کاربری
2. وارد کردن رمز عبور
3. اعتبارسنجی اطلاعات
4. ایجاد Session
5. انتقال به صفحه اصلی

---

## FR-03 : بازیابی رمز عبور

در صورت فراموشی رمز عبور، کاربر باید بتواند از طریق ایمیل رمز خود را بازیابی کند.

مراحل:

* وارد کردن ایمیل
* بررسی وجود ایمیل
* تولید Token امنیتی
* ارسال لینک بازیابی
* تعیین رمز جدید

---

## FR-04 : مشاهده لیست مقالات

کاربران باید بتوانند لیست مقالات منتشرشده را مشاهده کنند.

ویژگی‌ها:

* مرتب‌سازی
* صفحه‌بندی
* نمایش تصویر شاخص
* نمایش عنوان مقاله
* نمایش تاریخ انتشار

---

## FR-05 : مشاهده جزئیات مقاله

هر مقاله باید دارای صفحه اختصاصی باشد.

اطلاعات قابل نمایش:

* عنوان

* متن کامل
* نویسنده
* تاریخ انتشار
* دسته‌بندی

---

## FR-06 : فرم تماس با ما

کاربران می‌توانند پیام خود را برای مدیر سایت ارسال کنند.

اطلاعات فرم:

* نام
* ایمیل
* موضوع
* متن پیام

---

## FR-07 : دسته‌بندی مقالات

سیستم باید امکان گروه‌بندی مقالات را فراهم کند تا کاربران بتوانند مطالب را بر اساس دسته‌بندی مشاهده کنند.

---

## FR-08 : نوار کناری (Sidebar)

در تمامی صفحات سایت، یک نوار کناری پویا نمایش داده می‌شود که شامل:

* آخرین مقالات
* دسته‌بندی‌ها

است.

# نیازمندی‌های غیرعملکردی (Non-Functional Requirements)

این دسته از نیازمندی‌ها کیفیت عملکرد سیستم را مشخص می‌کنند.

---

## کارایی (Performance)

* زمان بارگذاری صفحات کمتر از دو ثانیه
* کاهش تعداد Queryهای پایگاه داده
* استفاده از Context Processor برای داده‌های عمومی
* بهینه‌سازی فایل‌های CSS و JavaScript

---

## امنیت (Security)

برای حفاظت از اطلاعات کاربران، سیستم باید موارد زیر را رعایت کند:

* جلوگیری از حملات SQL Injection
* جلوگیری از حملات XSS
* استفاده از CSRF Token در تمامی فرم‌ها
* هش کردن رمزهای عبور
* استفاده از Tokenهای امن برای بازیابی رمز عبور

---

## قابلیت نگهداری (Maintainability)

پروژه به صورت ماژولار طراحی شده است تا:

* توسعه آسان‌تر باشد.
* هر ماژول مستقل نگهداری شود.
* تست بخش‌های مختلف ساده‌تر انجام گیرد.

---

## مقیاس‌پذیری (Scalability)

معماری سیستم به گونه‌ای طراحی شده که در آینده بتوان بدون تغییر منطق برنامه، پایگاه داده SQLite را با PostgreSQL جایگزین کرد.

---

# اولویت‌بندی نیازمندی‌ها (MoSCoW)

برای مدیریت بهتر توسعه، نیازمندی‌ها بر اساس روش MoSCoW دسته‌بندی شده‌اند.

قابلیت‌هایی که نبود آن‌ها باعث ناقص بودن سیستم می‌شود:

* ثبت‌نام
* ورود
* مشاهده مقالات
* جزئیات مقاله
* فرم تماس
* امنیت پایه
* هش کردن رمز عبور

---

## SHOULD HAVE

قابلیت‌هایی که اهمیت بالایی دارند اما نبود آن‌ها مانع اجرای نسخه اولیه نیست:

* بازیابی رمز از طریق ایمیل
* صفحه‌بندی مقالات
* اسلایدر صفحه اصلی
* ذخیره پیام‌های تماس

---

## COULD HAVE

ویژگی‌هایی که ارزش افزوده ایجاد می‌کنند:

* صفحه درباره ما
* نمایش نویسنده مقاله
* استفاده از Context Processor
* پشتیبانی از PostgreSQL

---

## WON'T HAVE

قابلیت‌هایی که در محدوده این پروژه قرار ندارند:

* سیستم نظرات کاربران
* ویرایش مقاله توسط کاربران عادی
* پنل مدیریت اختصاصی
* API عمومی کامل

# ۳. متدولوژی توسعه نرم‌افزار (Software Development Methodology)

## مقدمه

برای توسعه پروژه **Blog Stand** از چارچوب چابک **Scrum** استفاده شده است. انتخاب این متدولوژی به دلیل ماهیت پویا و قابل تغییر پروژه، امکان دریافت بازخورد مستمر از ذی‌نفعان و توسعه تدریجی قابلیت‌های سیستم بوده است.

در Scrum، پروژه به چند بازه زمانی کوتاه (Sprint) تقسیم می‌شود و در پایان هر اسپرینت، یک نسخه قابل اجرا از نرم‌افزار ارائه می‌شود.

---

# چرا Scrum؟

دلایل انتخاب Scrum در این پروژه عبارت‌اند از:

* امکان تغییر نیازمندی‌ها در طول توسعه

* تحویل تدریجی قابلیت‌ها

* افزایش کیفیت محصول

* دریافت بازخورد مداوم

* مدیریت بهتر ریسک‌ها

* تقسیم مناسب وظایف میان اعضای تیم

* افزایش هماهنگی بین اعضا

* امکان برنامه‌ریزی دقیق برای هر مرحله توسعه

---

# ساختار تیم Scrum

تیم پروژه از پنج عضو تشکیل شده است که هر یک مسئولیت مشخصی در فرآیند توسعه بر عهده داشته‌اند.

# چرخه کاری Scrum

در این پروژه هر Sprint به مدت **دو هفته** برنامه‌ریزی شده است.

چرخه هر Sprint شامل مراحل زیر است.

---

## Sprint Planning

در ابتدای هر Sprint جلسه برنامه‌ریزی برگزار می‌شود.

فعالیت‌ها:

* بررسی Product Backlog

* انتخاب آیتم‌های Sprint

* تخمین زمان

* تقسیم وظایف

* تعیین هدف Sprint

---

## Daily Stand-up

جلسات کوتاه روزانه جهت بررسی وضعیت پروژه.

هر عضو به سه سؤال پاسخ می‌دهد:

* دیروز چه کاری انجام دادم؟

* امروز چه کاری انجام خواهم داد؟

* چه مشکلی دارم؟

---

## Sprint Review

در پایان Sprint:

* قابلیت‌های توسعه داده شده نمایش داده می‌شوند.

* بازخورد کاربران دریافت می‌شود.

* مشکلات احتمالی بررسی می‌شوند.

---

## Sprint Retrospective

در این جلسه تیم درباره موارد زیر گفتگو می‌کند:

* نقاط قوت Sprint

* مشکلات ایجاد شده

* راهکارهای بهبود

* پیشنهادهای اعضای تیم

---

# Sprintهای پروژه

## Sprint اول

### هدف

ایجاد زیرساخت اولیه پروژه

### فعالیت‌ها

* ایجاد پروژه Django

* طراحی ساختار اولیه

* طراحی مدل‌های پایگاه داده

* ایجاد Branchهای Git

* طراحی قالب اصلی سایت

* ایجاد ساختار اولیه Templateها

### خروجی‌ها

* معماری اولیه پروژه

* قالب اصلی صفحات

* مدل‌های اولیه پایگاه داده

* مخزن GitHub

* ساختار استاندارد پروژه

---

## Sprint دوم

### هدف

پیاده‌سازی قابلیت‌های اصلی سیستم

### فعالیت‌ها

* پیاده‌سازی ثبت‌نام

* ورود کاربران

* خروج از سیستم

* بازیابی رمز عبور

* مدیریت مقالات

* طراحی Sidebar

* فرم تماس

* ارسال ایمیل

* تست اولیه پروژه

### خروجی‌ها

* سیستم احراز هویت

* سیستم بازیابی رمز عبور

* ارسال ایمیل

* لیست مقالات

* جزئیات مقاله

* فرم تماس

* Sidebar پویا

# معماری سیستم

## نمای کلی

پروژه بر اساس معماری **Monolithic Web Application** توسعه یافته است.

در این معماری تمامی ماژول‌ها در یک برنامه Django قرار دارند و با استفاده از معماری MTV با یکدیگر تعامل می‌کنند.

مزایای این معماری:

* توسعه سریع

* سادگی نگهداری

* استقرار آسان

* هماهنگی بهتر بین ماژول‌ها

* مناسب برای پروژه‌های کوچک و متوسط

---

این لایه مسئول ارتباط با کاربر است.

این لایه مسئول ارتباط با پایگاه داده است.

وظایف:

# الگوهای طراحی (Design Patterns)

در پروژه برای افزایش کیفیت کد از چند الگوی طراحی استفاده شده است.

---

## MVC / MTV

ساختار اصلی پروژه بر پایه معماری MTV در Django است که باعث جداسازی مناسب داده، منطق و رابط کاربری می‌شود.

---

## Service Layer

منطق‌های پیچیده برنامه در لایه Service قرار گرفته‌اند تا Viewها ساده‌تر و قابل نگهداری‌تر باشند.

مزایا:

* افزایش خوانایی

* قابلیت تست بهتر

* کاهش وابستگی

---

## Context Processor

برای ارسال اطلاعات عمومی مانند دسته‌بندی‌ها و آخرین مقالات به تمام صفحات، از Context Processor استفاده شده است.

مزایا:

* حذف کدهای تکراری

* کاهش Queryهای اضافی

* افزایش کارایی

---

## Token Factory

برای تولید Tokenهای امن بازیابی رمز عبور از ساختاری مستقل استفاده شده است.

ویژگی‌ها:

* یکبار مصرف

* دارای زمان انقضا

* امنیت بالا

---

## Repository (Django ORM)

برای ارتباط با پایگاه داده از ORM جنگو استفاده شده است.

مزایا:

* جلوگیری از SQL Injection

* خوانایی بیشتر

* قابلیت تغییر پایگاه داده

* مدیریت آسان Migrationها
